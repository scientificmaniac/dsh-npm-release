# v1.0.2

发布日期：2026-11-19

这一版修的是 **v1.0.1 的修复动作本身引入的问题**。v1.0.1 为堵住泄露与误判加了检查，
而这些新检查在真实发布里又暴露了四处缺陷；本版把它们逐一修掉，并补上真正能拦住回归的测试。

## 修复

- **失效 token 不再报成「不影响发布」。** 之前删除包时 token 一并失效，`npm token list`
  返回 `E401`，但旧代码把它归成「没有读 token 列表的权限，不影响发布」，于是 `check`
  全绿、`publish` 直接 401。现在带凭据拿到 401 会判为阻断项，并提示重新登录。
- **授权链接打码识别覆盖全部文案。** 之前只认 `/auth/cli/***`，漏了 `login?next=/login/cli/***`：
  那条链接会被当成真链接交给用户。现在判据是「提取出的 URL 里含 `***` 即打码」，
  打码链接不再交出，改为提示去有 TTY 的真终端执行。
- **泄露报告本身不再泄露。** AWS 密钥 `AKIA…` 之前因脱敏规则漏了这个前缀而原样写进报告；
  回环地址的真实端口也会原样出现。现在两者都脱敏。
- **POSIX 主目录不再大量漏报。** `/home/<name>` 后跟空格、逗号、`&&`、子路径时之前不命中
  （error 级规则漏报）；同时把文档里正确的占位写法与真实路径区分开，不误报。
- **`unpublish` 状态判定有了真正的测试保护。** 之前把该判定整个删掉，全套测试仍会通过；
  现在判定逻辑抽成纯函数并直接断言，变异测试可让相关用例失败。
- **24 小时冷却期与权限拒绝区分开。** 重新发布被 unpublish 过的包时，npm 报的是 403，
  旧代码据此让用户去查 token scope；现在单独识别为冷却期，说明「不是凭据问题，等满 24 小时」。
- **泄露检查不再拦截自己的规则文本。** 检查器注释里的示例路径曾稳定产生 error，
  把本插件挡在发布之外；现在按文件排除规则定义，并测试同名其它文件不受影响。
- **测试跨平台稳定。** `describeSpawnError` 的断言改为显式注入平台，去掉两处无保护力的真实网络调用；
  CI 在 Node 20、22、24 上全部通过。

## 兼容性

无破坏性变更。五个动作（`check` / `pack` / `publish` / `verify` / `status`）的参数与输出格式均保持兼容。

## 验证

- 单元测试：227 项通过。
- 变异测试：废掉 `unpublish` 判定会让 3 项失败；去掉 `AKIA` 脱敏会让 1 项失败。
- CI：Ubuntu 上的 Node 20、22、24 三个版本全部通过。
- 从 npm 实际安装本版本：21 个文件齐全，工具可注册，`status` 可执行；
  本地 integrity 与 registry 一致。

## 升级

直接从旧版本更新即可，无需迁移配置。

> 本版本为纯修复版，未新增需要用户操作的功能。
